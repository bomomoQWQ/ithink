# 首版实现约定

日期：2026-11-15。本文收窄旧草案，不把前面对话中助手的建议自动视为用户已经确认。

## 已确认

- 独立、通用、开源的 harness：轻、快、模块化，使用 Rust。
- 内核的三个主体部件：通信调度器、任务管理器、主体管理。
- 会话和具体模型、工具、派活拓扑属于用户态。主体层级：0 用户、1 主 agent、2 worker、3 一次性子代理；层级不自动等于权限或 CPU 优先级。
- 上下文管理在内核；压缩策略在插件，内核提供受校验的上下文替换，不静默截断原文。
- 插件由内核启动，独立进程运行，通过公开 API 交互，支持运行时加载、替换、卸载。
- 系统交互桥的另一端也可由插件提供。后端结果和错误保留，不替后端归一化。

## 首版范围

- 一个核心 Rust 库（workspace 中的 `ithink-core`，库名 `ithink`），使用标准库线程和消息通道；不强迫宿主引入异步运行时。
- 进程间协议使用有大小限制的逐行 JSON：握手、请求、响应、事件。每条连接绑定内核分配的 AID，消息不能自报身份提升权限。
- 同一个内核循环分派请求；慢系统操作交给后端插件，不在主循环里等待。每条进程输出有有界缓冲，防止无限积压。
- 工作代理可通过宿主预授权的模板启动，父主体能明确传入初始上下文、管理生命周期，不能自动读取后续私有上下文。
- 系统调用可按服务及操作分别授权，可绑定任务。取消会终止关联待办并通知后端；外部操作需协作取消，副作用不保证撤回。
- 新实例握手成功后切换路由；失败保留旧实例；替换或卸载会使旧实例未完成请求明确失败。首版不承诺自动迁移插件进程内状态。
- 保留原文及替换记录；压缩只替换发送视图。上下文窗口按任务分别核算，不将多个独立模型请求的窗口相加。
- 运行层级作为主体元数据，首版不实现强制 CPU 抢占、不实现自动主 agent 重启。

## 公开的安全边界

独立进程可隔离普通插件退出/崩溃，但不等于安全沙箱。第一版协议要求插件通过内核 API 请求系统交互；没有操作系统限制时，恶意本机程序仍能自行调用系统。安全沙箱、进程树级资源限制及多平台强隔离后续单独实现，不能用隐藏工具或能力标签替代。

## 不继承的旧假设

- 不规定轻、快、模块化三者的用户优先级；未基准测试前不声称达到旧草案数值。
- 不把会话等同于某一级任务，不把主体等同于任务，两类 ID 独立。
- 不将层级自动映射为抢占优先级，不声称 Rust 可安全强杀任意线程。
- 不为前缀缓存硬编码某个提供方的切块规则；输入未被替换时原样保存。
- 不提供默认丢最旧/剪头尾的内核压缩。压缩失败报告错误，原视图保留。
- 不承诺本机原生插件能被普通 API 限制访问系统。
